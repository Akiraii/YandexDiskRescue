# Yandex Disk Rescue — PowerShell Edition

**Новый основной интерфейс:** `Start-YandexDiskRescue.cmd` → `YandexDiskRescue.ps1` → GUI WPF. **Код полностью на PowerShell 5.1**, C# GUI и установка .NET SDK не нужны. Windows 10/11 x64, PowerShell 5.1 в составе Windows. На ПК пользователя должны присутствовать штатные PowerShell/WPF и Chrome для режима безлимита.

## Установка

1. Скачайте артефакт `YDR-PowerShell-Portable` из GitHub Actions, распакуйте в обычную папку, например `D:\YDR-PowerShell`.
2. Откройте **`Start-YandexDiskRescue.cmd`**. Не запускайте как администратор.
3. Получите OAuth-токен на [официальном Полигоне Яндекс Диска](https://yandex.ru/dev/disk/poligon/) через кнопку GUI. Никому не отправляйте токен.
4. Введите токен и нажмите «Проверить». Для фоновых заданий разрешите DPAPI-хранение текущим пользователем.
5. Выберите папку на Яндекс Диске (пусто = весь Диск), папку на локальном/USB-диске, добавьте задание в очередь.
6. Работа продолжится в фоновом `YDR.Worker.ps1` даже после закрытия GUI. Он не устанавливает системную службу. Настройка автозапуска включается вручную.

**В отличие от старой версии:** для PowerShell-приложения не требуется `YandexDiskRescue.exe` или `Rescue.Worker.exe`. ZIP содержит PS-скрипты, XAML, проверенные `tools/rclone.exe`, `tools/node.exe`, `tools/yd.js`, `playwright-core` и зависимости.

## Безопасное копирование

- Используется **`rclone copy`**, а не `sync`, с `--immutable`, затем `rclone check --download` по содержимому. Программа не удаляет локальные файлы и оригиналы на Яндексе.
- Токен передаётся в окружении дочернего `rclone.exe` и по запросу пользователя хранится в DPAPI CurrentUser (`%LOCALAPPDATA%\YandexDiskRescue\PowerShell\config\token.dpapi`). Сам OAuth-токен не передаётся в аргументах процесса.
- Встроенные `rclone.exe`, `node.exe` запускаются только из `tools`, поиск в системном `PATH` запрещён. Помощник `yd.js` проверяется по SHA-256.
- Очередь в `data/jobs.json` записывается атомарно, с именованным межпроцессным mutex; это **не** миграция из старого C#/SQLite. Старые данные остаются нетронутыми.
- Привязка задания к серийному номеру локального тома предотвращает молчаливую запись на другой USB-диск.
- Логи остаются локально, OAuth и известные поля авторизации маскируются; перед передачей диагностических файлов третьим лицам всё равно проверьте их содержимое.

## Фото из безлимита

Сначала запускайте только на **отдельном тестовом Яндекс-аккаунте**. Вкладка «Фото из безлимита»: проверить квоту → открыть отдельный Chrome и войти в него → собрать список → явно подтвердить перенос → скачать и проверить. Мастер выполняет эти действия последовательно, но только после отдельного подтверждения изменения облачных данных.

**Важно:** перенос через недокументированный веб-API Яндекса `/models-v2` **изменяет облачные пути** и расходует обычную квоту. Chrome используется с локальным TCP-портом DevTools; другие локальные программы на компьютере могут получить к нему доступ, пока порт открыт. Не запускайте такую операцию на недоверенном ПК. Закройте Chrome после операции.

## Структура

- `YandexDiskRescue.ps1` — WPF GUI + обработчики событий, реализованы в PowerShell.
- `MainWindow.xaml` — внешний вид, без C# code-behind.
- `YDR.Core.psm1` — очередь JSON, DPAPI, безопасный запуск процессов, квота, логирование, отчёты.
- `YDR.Worker.ps1` — фоновая очередь, копирование, проверка и операции безлимита.
- `Start-YandexDiskRescue.cmd` — запуск GUI с `-STA`, без постоянного изменения ExecutionPolicy.
- `qa/Smoke.ps1` — Windows PowerShell 5.1 AST/XML и минимальные функциональные тесты без подключения к Яндексу.

## Что не проверено

Успешная сборка и статические тесты **не доказывают** отсутствие утечек данных, корректность всех ответов веб-API Яндекса и полноту скачивания. Требуется реальный Windows-тест со специальным тестовым аккаунтом, проверкой CDP и анализом сетевого трафика. Для основного семейного архива не рекомендуется использовать экспериментальный перенос до этих испытаний.
